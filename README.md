# Software Factory

Research and drafts for **"The Agentic PDLC: building a software factory around a high-scale service"**: how to agentify the product development lifecycle of an existing, high-scale enterprise service safely, grounded in published evidence (Microsoft first).

The assembled document lives as a Claude Doc; this repo holds its sources, section drafts, review reports, diagrams and tooling. The latest PDF build is [`published/agentic-pdlc.pdf`](published/agentic-pdlc.pdf).

## Layout

| Path | What it holds |
|---|---|
| `SOURCES.md` | Index of every source read, with IDs and evidence grades (A/B/C). |
| `sources/` | One structured note per source cluster (summary, mechanisms, numbers, quotes, PDLC stages). |
| `document/00-skeleton.md` | The approved outline: every part and section, its brief, sources and planned diagrams. |
| `document/01-conventions.md` | Writing and QC rules, including review feedback folded in. |
| `document/sections/` | Section drafts: `0` front matter, `I` lessons, `II.1`–`II.12` PDLC stages, `III` trust model, `IV` enterprise complexity, `V.1`–`V.2` service catalog and reference architecture, `VI`, `VII`, and appendices `A` (glossary), `C` (gaps), `D`/`D1` (implementation kit, PRD template), `E` (requirements). |
| `document/diagrams/` | Main diagrams as `.excalidraw` files (open at [excalidraw.com](https://excalidraw.com) or the VS Code extension). |
| `document/qc/` | Per-section review reports: `*-grounding.md` (claims checked against sources) and `*-reader-judge.md` (readability review), plus the cross-document consistency report. |
| `document/references.md`, `references.json` | Reference registry mapping short codes (e.g. `MS4`) to sources. |
| `document/*-todo.md`, `kit-proposals.md`, `req-renumber-map.md` | Working notes from assembly. |
| `published/` | Build output: `agentic-pdlc.pdf`, plus the assembled `agentic-pdlc.md`/`.html` and the Excalidraw diagrams as SVG. Regenerated by the build; commit it to publish a revision. |
| `tools/` | `build_refs.py` (builds the reference registry), `to_codes.py` (rewrites source IDs to short codes), `validate.js` (renders Mermaid blocks headlessly and checks readability), `build-pdf.mjs` (the PDF build, below). |

Note: the tools use absolute paths from the original workspace (`/mnt/project-files/software-factory-research`); adjust the root path to run them from a clone.

## Building the PDF

One command rebuilds the whole document into `published/agentic-pdlc.pdf`:

```bash
make build        # or ./build.sh, or npm install && npm run build
```

**Prerequisites:** Node.js 18 or later and npm. The first run installs the npm packages (`marked`, `mermaid`, `@excalidraw/utils`, `playwright`) and downloads Playwright's headless Chromium (`npx playwright install chromium`). After that the build runs offline in about 10 seconds. To use a Chromium you already have, set `CHROMIUM_PATH=/path/to/chromium`.

What it does (`tools/build-pdf.mjs`):

1. Assembles `document/sections/*.md` in document order: Part 0, I, II.1 to II.12 (under a Part II heading), III, IV, V.1 and V.2 (under a Part V heading), VI, VII, then Appendices A, B (`document/references.md`), C, D (with D1 placed before D2) and E. Per-section "Open gaps" lists are dropped because Appendix C collects them, matching the Claude Doc. The order lives in the `ORDER` list at the top of the script.
2. Renders each `document/diagrams/*.excalidraw` to SVG and places it as a figure at the end of its subsection (the `FIGURES` list: uber chart in 0.4, II.2, II.9, III.4, V.1, V.2).
3. Renders every Mermaid block, adds a cover page (build date and commit) and a table of contents, and prints an A4 PDF with page numbers and PDF bookmarks.

The build fails if a Mermaid block does not render, a figure anchor is missing, or an image fails to load. To publish a revision: edit the section files, run `make build`, and commit `published/` with your changes.
