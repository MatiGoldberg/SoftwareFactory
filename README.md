# Software Factory

Research and drafts for **"The Agentic PDLC: building a software factory around a high-scale service"**: how to agentify the product development lifecycle of an existing, high-scale enterprise service safely, grounded in published evidence (Microsoft first).

The assembled document lives as a Claude Doc; this repo holds its sources, section drafts, review reports, diagrams and tooling. The latest PDF build is [`published/agentic-pdlc.pdf`](published/agentic-pdlc.pdf).

## Layout

| Path | What it holds |
|---|---|
| `SOURCES.md` | Index of every source read, with IDs and evidence grades (A/B/C). |
| `sources/` | One structured note per source cluster (summary, mechanisms, numbers, quotes, PDLC stages). |
| `document/00-skeleton.md` | The approved outline: every part and section, its brief, sources and planned diagrams. |
| `document/01-conventions.md` | Writing and QC rules, including review feedback folded in. |
| `document/sections/` | Section drafts: `0` front matter, `I` lessons, `II.1`–`II.12` PDLC stages, `III` trust model, `IV` enterprise complexity, `V.1`–`V.2` service catalog and reference architecture, `VI`, `VII`, and appendices `A` (glossary), `C` (gaps), `D`/`D1` (implementation kit, PRD template), `E` (requirements). |
| `document/diagrams/` | Main diagrams as `.excalidraw` files (open at [excalidraw.com](https://excalidraw.com) or the VS Code extension). |
| `document/qc/` | Per-section review reports: `*-grounding.md` (claims checked against sources) and `*-reader-judge.md` (readability review), plus the cross-document consistency report. |
| `document/references.md`, `references.json` | Reference registry mapping short codes (e.g. `MS4`) to sources. |
| `document/*-todo.md`, `kit-proposals.md`, `req-renumber-map.md` | Working notes from assembly. |
| `published/` | Build output: `agentic-pdlc.pdf`, plus the assembled `agentic-pdlc.md`/`.html` and the Excalidraw diagrams as SVG. Regenerated by the build; commit it to publish a revision. |
| `assets/` | PDF look and feel: `theme.css` (colours, fonts, headings, tables, callouts), `logo.svg` (cover logo) and `fonts/` (bundled Inter and JetBrains Mono, SIL Open Font License). |
| `tools/` | `build_refs.py` (builds the reference registry), `to_codes.py` (rewrites source IDs to short codes), `validate.js` (renders Mermaid blocks headlessly and checks readability), `build-pdf.mjs` (the PDF build, below). |

Note: the tools use absolute paths from the original workspace (`/mnt/project-files/software-factory-research`); adjust the root path to run them from a clone.

## Building the PDF

```bash
make build                     # default: Excalidraw figures where they exist
make build DIAGRAMS=mermaid    # every diagram from Mermaid
make help                      # all options
```

The same options work on the script directly: `node tools/build-pdf.mjs --diagrams mermaid` (or `-d mermaid`, `--diagrams=mermaid`), `./build.sh -d mermaid`, or `npm run build -- --diagrams=mermaid`. Note the extra `--` with npm: without it npm keeps the option for itself, and the build stops with an error that says so.

**Prerequisites:** Node.js 18 or later and npm. The first `make build` runs `npm install` and `npx playwright install chromium`; after that the build runs offline in about 15 seconds. To use a Chromium you already have, set `CHROMIUM_PATH=/path/to/chromium`.

### Options

| Option | Values | Meaning |
|---|---|---|
| `-d`, `--diagrams` | `excalidraw` (default), `mermaid` | Which version of each diagram goes in (see below). Also read from the `DIAGRAMS` environment variable. |
| `-h`, `--help` | | Prints usage and exits. |

The arguments are strict: an unknown option, a wrong-case option (`--DIAGRAMS`), a missing or unknown value, a repeated option or a stray argument stops the build with exit code 2, an error message and the usage text.

### Output: one folder per run

Every run writes a new folder and never overwrites an earlier one:

```
published/
  agentic-pdlc.pdf                      latest excalidraw-mode build (stable name, committed)
  agentic-pdlc-mermaid.pdf              latest mermaid-mode build (stable name, committed)
  builds/                               not committed (.gitignore); `make clean` removes it
    2026-11-17_043436_6287a93_excalidraw/
      agentic-pdlc_2026-11-17_043436_excalidraw.pdf
      agentic-pdlc_2026-11-17_043436_excalidraw.md     assembled Markdown
      agentic-pdlc_2026-11-17_043436_excalidraw.html
      diagrams/*.svg                                   rendered Excalidraw panels
```

The folder name is the local date and time, the commit, and the mode; a second run in the same second gets a `-2` suffix. A failed run deletes its half-written folder. The PDF cover page shows the build date, commit and diagram mode, and says "with local edits" when `document/` has uncommitted changes. To publish a revision, run `make build` and commit the updated `published/agentic-pdlc.pdf`.

### Steps

The console shows a banner and one traced line per step, with timings:

1. **Check inputs:** every section file in the document order, the Excalidraw files and the npm packages exist.
2. **Start headless Chromium.**
3. **Render Excalidraw figures** (excalidraw mode only): multi-panel `.excalidraw` files are cropped into their panels and exported to SVG.
4. **Assemble sections** in document order: Part 0, I, II.1 to II.12 (under a Part II heading), III, IV, V.1 and V.2 (under a Part V heading), VI, VII, then Appendices A, B (`document/references.md`), C, D (with D1 placed before D2) and E. Per-section "Open gaps" lists are dropped because Appendix C collects them, matching the Claude Doc. The order is the `ORDER` list at the top of `tools/build-pdf.mjs`.
5. **Render HTML, fonts and Mermaid diagrams.** Loads the bundled fonts, renders Mermaid in the theme's colours, and moves a wide diagram onto its own landscape page when that prints it at least 25% larger (`LANDSCAPE_GAIN`). Fails if any font, Mermaid block or image does not load or render. The log lists the landscape pages and counts the callout boxes.
6. **Print PDF, two passes:** the first pass finds the page of every heading (from the PDF bookmarks); the second fills those page numbers into the contents. Fails if filling them in moves any heading.
7. **Add running headers, page numbers and metadata:** every page but the cover gets a footer with the page number; every page but the cover and the Part and appendix openers gets a header with the Part on the left and the current section on the right. Sets the PDF title.
8. **Publish latest copy** to the stable name above.

### Look and feel

The PDF follows a clean technical-book layout: A4, Inter for text and JetBrains Mono for code (both bundled in `assets/fonts/`, so the build needs no network), deep blue with an orange accent, a cover with the logo and the build date and commit, a contents page with page numbers, a page per Part and per PDLC stage, shaded code blocks and striped tables.

- **Colours, fonts, spacing:** `assets/theme.css`. The palette is the `:root` variables at the top; Mermaid's colours are `MERMAID_THEME` in `tools/build-pdf.mjs`, and the header and footer colours are in `stampPages()` there.
- **Logo:** replace `assets/logo.svg` with your own (any aspect ratio; it is fitted into a square). A `logo.png` is used instead if there is no `logo.svg`.

### Callout boxes (Takeaway, Note, Tip, Warning)

A blockquote whose first word is one of four bold labels becomes a shaded box. Write it in the section file like this; GitHub and other Markdown viewers show it as a plain quote:

```markdown
> **Takeaway:** the bottom line a reader should not miss.

> **Note:** background or a clarification.

> **Tip:** a practical suggestion.

> **Warning:** a pitfall or a risk.
```

The label must be exactly `**Takeaway:**`, `**Note:**`, `**Tip:**` or `**Warning:**` (bold, with the colon inside) at the start of the quote. Any other blockquote prints as an ordinary indented quote. Use **Takeaway** sparingly, about one per section, for the message worth a reader's attention; the existing ones wrap a sentence that was already in the text (each stage's "Recommendation, in one line", each "So for an existing service" lesson in Part I, the executive summary's "decision for you now", and the bottom lines of Parts III, IV, V and VI).

### Choosing the diagram source

Twelve of the 37 Mermaid blocks also exist as hand-drawn Excalidraw panels in `document/diagrams/`. The build includes exactly one version of each diagram:

- **`excalidraw`** (default): 11 Excalidraw figures replace those 12 Mermaid blocks (0.4 uber chart, II.2 ×2, II.9 ×2, III ×2, V.1 ×3, V.2; the one Excalidraw uber chart covers both 0.4 charts). The other 25 diagrams stay Mermaid.
- **`mermaid`**: all 37 diagrams from Mermaid; no Excalidraw.

The pairing of Excalidraw panels to Mermaid blocks, with each panel's crop box, is the `FIGURES` list in `tools/build-pdf.mjs`. If you add a Mermaid block ahead of an existing one in those six sections, update the block numbers there; the build fails if a listed block no longer exists.
