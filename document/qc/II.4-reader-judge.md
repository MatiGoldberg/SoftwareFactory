## Concrete edits

1. **Fix the L3 contradiction (biggest issue).** Table row "Breaking-change agent | Act, then notify (L3) | Runs the same diff tool before the PR ..." and the sentence "Act, then notify is safe for the breaking-change agent only because a diff and a comment change nothing." A diff and a comment are not a pre-approved action, so this is Advise relabelled; next to "no agent applies an approval label" it reads as rung inflation. Replace with two rows: "Advise (L0): runs the diff on the author's draft before the PR, explains each flagged change, proposes a non-breaking alternative" and "Act, then notify (L3): posts its findings on every spec-repo PR automatically and adds the non-blocking label `BreakingChangeReviewRequired` early, never `Approved-BreakingChange`; CI's label stays authoritative". Rewrite the sentence as: "Its highest rung only adds information and blocking labels, never removes or approves them, which is why Act, then notify is safe."
2. **Separate the judge from the drafter.** Design-critique agent row "Prepare (L1) | Drafts the threat model's first pass ..." contradicts "it must not be the agent that drafted the contract" and the "separate from the drafting agent" guardrail: the same role would then critique its own threat model. Move this row to a new "Threat-model agent" role (or under the contract and compat agent) and add to the guardrail "critiqued by the design-critique agent, never by itself".
3. **Disambiguate "Prepare".** The AWS phase and the L1 rung share a name. In prose and the table write "the Prepare phase" / "the Activate phase" every time (e.g. "Prepare/Activate split" -> "Prepare-phase/Activate-phase split"), and change the chart-2 edge label `"Prepare: OpenAPI diff,<br/>compat plan"` to `"Prepare (L1): OpenAPI diff,<br/>compat plan"`.
4. **Move the Real-world reference ahead of its first use, or add one-line glosses.** In "Breaking-change diff" replace "tooling compares it with the latest released versions (see the reference below)" with "Azure's tooling (azure-openapi-diff) compares it with the latest GA and preview versions and labels breaking changes, which only a human board can clear [MS25]." In "Compatibility plan" add "AWS's two-phase deployment ships the ability to read a new format before it starts writing it [AWS3]" before naming the phases.
5. **Cut the "Versioning rules" bullet from "Gates in the chart".** It is not a gate in the chart and is the longest bullet. Keep only "Any behavior change requires a new dated API version [MS25]" as one sentence inside the "Breaking-change diff" bullet; drop "design for change up front (extensible string enums, ETags, server-side paging from day one) and ship at least two previews before GA [MS26]; reportedly, changing status or error codes or adding pagination later counts as breaking [MS26]" and the 3-year/90-day detail (already in REQ-API-03). Saves about 80 words.
6. **Trim the Azure explainer.** Cut "detects 47 kinds of change," and "Azure's guidelines add an API Stewardship Board to engage early, and a deprecation header, because emails to owners often do not reach the developers who call the API [MS26]." (The Stewardship Board is never used again; the deprecation header can become a clause in REQ-API-03 if wanted.) Add who the board is: "the Breaking Change Review Board (Azure API reviewers who must approve any breaking change)".
7. **Trim the AWS explainer.** Cut "AWS versions serializers independently of builds, stores the version with the data and preserves unknown attributes [AWS3]." Specialist detail; II.9 already carries the execution side. Also gloss "one-way doors" on first use in Purpose: "one-way doors (changes that cannot be rolled back)".
8. **Add the consumer-acknowledgement gate to chart 1.** REQ-OWN-02 and the first Enterprise bullet make consumer acknowledgement a gate input, but chart 1 has no node for it. Add `CP --> ACK["Consumer owners ack<br/>from catalog"]` and `ACK --> GATE` (or fold into the Compatibility plan node label: `"Compat plan +<br/>consumer acks"`) and add a gates bullet: "Consumer acknowledgement. Owners listed from the service catalog (see V.1) acknowledge a breaking or deprecating change." To keep width, merge `DR` into the HLD row or drop the separate `Review board` node into the diff label (`"labelled: board"`), since text is already at 12.7px.
9. **Align chart 2 with the table.** The table says the breaking-change agent runs "before the PR", but the chart draws `PR --> BCA`. Either connect `CDA --> BCA --> PR` (pre-PR check) or change the table text to "on each PR".
